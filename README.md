# Кооп-платформер (2-4 игрока)

2D платформер с видом сбоку для совместного прохождения 2-4 игроками.
Цель — добраться всей командой до финиша. Никакой регистрации, никакого
интернета: фронтенд на чистом HTML5 Canvas + JS, сервер на Go (только
стандартная библиотека).

## Структура

```
platformer/
├── frontend/        # index.html + game.js — статика, раздаётся сервером
├── server/          # Go WebSocket-сервер (net/http, encoding/json — без зависимостей)
├── ollama-mcp/       # существующий MCP-сервер для Ollama (используется отдельно, см. ниже)
└── README.md
```

## Запуск

Требуется только установленный Go (1.21+).

```bash
cd platformer/server
go run .
```

Сервер поднимется на `http://localhost:8080` и сам раздаёт файлы из
`frontend/`. Откройте этот адрес в браузере — этого достаточно, чтобы
играть одному.

Порт можно поменять переменной окружения `PORT`.

## Подключение второго (третьего, четвёртого) игрока

Откройте `http://localhost:8080` в **другой вкладке/окне браузера** (или с
другого устройства в той же сети — `http://<IP-машины-с-сервером>:8080`).
Каждый игрок вводит своё имя и нажимает «Войти в игру» — комната
рассчитана максимум на 4 одновременных подключения, пятому игроку сервер
ответит, что комната заполнена.

Управление: `A`/`D` или `←`/`→` — движение, `W`/`↑`/`Пробел` — прыжок.
Игра кооперативная: флаг засчитывается только когда **все** подключённые
игроки одновременно стоят на финишной платформе.

## Комната ожидания

Подключение теперь не бросает игрока сразу в игру:

1. После ввода имени игрок попадает в **комнату ожидания** со списком всех
   подключённых (цвет + готовность).
2. Каждый нажимает «Готов». Старт возможен только если **готовы минимум
   2 игрока** — иначе под кнопкой видна подсказка, сколько ещё нужно.
3. Когда условие выполнено — стартует 5-секундный обратный отсчёт, цифры
   которого с подпрыгиванием и неоновым цветом выскакивают на экран
   (и пищат), сервер генерирует новый уровень для всей команды одновременно.
4. Если кто-то подключается **во время уже идущего раунда**, он попадает в
   очередь зрителей (это видно остальным в списке: «Зрителей в очереди: N»)
   и автоматически становится игроком следующего раунда.
5. После победы — 6 секунд на конфетти, затем сервер сам возвращает всех в
   комнату ожидания для следующего раунда (готовность сбрасывается, уровень
   будет новый).

## AI-интеграция (локальная Ollama)

В проекте уже есть готовый MCP-сервер `ollama-mcp/` — он используется
Claude Code как ассистентом для разгрузки тривиальных задач на локальную
модель (например, черновик unit-тестов для `assignColor` в
`server/main_test.go` был накидан именно через него, а затем поправлен
вручную под реальные типы) и не имеет отношения к самой игре напрямую.

Для самой игры выбрано другое, более полезное применение: **Go-сервер сам
обращается напрямую к локальному Ollama HTTP API** (`POST
http://localhost:11434/api/generate`, см. `server/ai_narrator.go`).

Почему именно так и для чего:
- Когда команда часто срывается с платформ (каждое третье падение,
  не чаще раза в 20 секунд), сервер просит модель придумать короткую
  фразу поддержки/подсказку на русском и разослать её всем игрокам —
  это живой, не повторяющийся комментарий «рассказчика», который реально
  меняет ощущение от игры, а не статичная надпись.
- Запрос асинхронный и не блокирует игровой цикл; если Ollama не запущена
  или недоступна, сервер автоматически берёт одну из заготовленных фраз —
  игра работает одинаково хорошо с локальной AI и без неё.
- Других мест, где AI добавляла бы реальную ценность здесь (физика, сеть,
  рендер), не нашлось — намеренно не стали добавлять AI «для галочки».

Чтобы услышать живые AI-подсказки, перед запуском сервера поднимите Ollama:

```bash
ollama serve
ollama pull llama3   # один раз, если модель ещё не скачана
```

Адрес и модель настраиваются переменными окружения `OLLAMA_HOST` и
`OLLAMA_MODEL` (по умолчанию `http://localhost:11434` и `llama3`).

## Технические детали

- WebSocket-протокол реализован вручную на стандартной библиотеке
  (`server/ws.go`) — без `gorilla/websocket` и любых внешних модулей.
  Запись во фрейм синхронизирована мьютексом на соединение: разные горутины
  (ready-обработчик, таймер отсчёта, рассылка позиций) могут одновременно
  слать сообщения одному клиенту, и без блокировки их байты переплетались
  бы в один TCP-сегмент, ломая структуру фрейма — клиент видел это как
  мгновенный разрыв соединения.
- Если соединение с сервером пропадает (вкладка партнёра закрылась, упала
  сеть), клиент теперь явно показывает «Соединение потеряно» и возвращает
  на экран ввода имени, а не зависает молча на последнем известном кадре.
- Камера следует за игроком и по X, и по Y (`frontend/game.js`, `render`).
  Уровень по вертикали выше канваса (платформы и старт лежат у y≈620-680
  при высоте канваса 540px) — без вертикального скролла игрок и платформы
  отрисовывались за нижней границей экрана, и игра выглядела как пустой
  фон без персонажей.
- Сразу после старта раунда сервер шлёт и `start` (с уровнем), и следом
  `lobby`-снимок (чтобы зрители в очереди увидели смену состояния). Клиент
  раньше обрабатывал `lobby` безусловно и возвращал экран в комнату
  ожидания, затирая только что показанную игру — теперь `lobby` игнорируется
  для тех, кто уже в раунде.
- Уровень генерируется процедурно на сервере при старте раунда
  (`server/level.go`) и одинаков для всех игроков сессии. Вместо одной
  однородной цепочки платформ уровень собирается из случайно
  перемешанных стилевых секций — обычные гэпы, лестницы, парящие
  острова, узкие мостики на точность, зигзаги — поэтому каждый раунд
  ощущается структурно по-разному, а не только координатами платформ.
  Между секциями расставлены чекпоинты (золотая платформа с флажком):
  упав, игрок возрождается на последнем пройденном чекпоинте, а не
  всегда в начале уровня.
  `TestGenerateLevelIsJumpable` прогоняет 200 сидов и проверяет, что ни
  один гэп/перепад высоты не превышает физически прыгаемые пределы.
- Физика (гравитация, прыжок, коллизии) считается на клиенте; сервер
  только синхронизирует позиции игроков и общий прогресс — это кооп-игра
  без анти-чита, упрощение оправдано масштабом проекта.
- Персонажи рисуются как человечки (голова/туловище/руки/ноги) с
  анимацией ходьбы и прыжка, а не плоскими прямоугольниками
  (`drawHuman` в `frontend/game.js`).
- Фон — лёгкий параллакс (облака и холмы движутся медленнее камеры),
  победа сопровождается конфетти и звуком, прыжок и победа озвучены через
  WebAudio (звук синтезируется на лету, без файлов-ассетов).
- Визуал сделан максимально психоделическим: непрерывный hue-rotate всего
  canvas, неоновые светящиеся платформы, радужный флаг финиша, плавающие
  цветные кольца на фоне, радужный шлейф за каждым персонажем и тряска
  экрана при жёстком приземлении/падении/победе.
